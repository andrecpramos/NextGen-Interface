# ADR-018 — The product is one folder that is copied, not a set of packages that are installed

- **Status:** Accepted — 2026-09-17
- **Date:** 2026-09-17
- **Deciders:** Maintainers
- **Supersedes:** —
- **Extends:** [ADR-013](./ADR-013.md) — that decided *what* the product is; this decides
  how it is delivered.
- **Makes moot:** [ADR-016](./ADR-016.md). Its subject was two domain packages colliding
  on one registry path. Both domains are deleted here, so the collision cannot recur;
  the per-domain layout it chose survives as the per-role layout `adapter/` emits.

## Context

This repository carries two products, and has since the pivot.

The root `package.json` still describes the first one:

> *"AI-native application platform. Conversation is the interface; screens are what the AI drives."*

The README describes the second:

> *"A drop-in AI navigation layer for a web app that already exists."*

The dependency graph shows the split is not rhetorical. Of twelve packages, six are on
the path to an adopter and six are reachable **only** from the terminal demo:

```
ships:  kit -> generator, embed, core-intent -> core-capability, core-inference
demo:   apps/cli -> core-dispatch, core-trace, core-voice, data,
                    domain-modules, domain-finance
```

That second row is 8,538 lines, plus 1,164 in `apps/cli`. Nothing on the shipping path
imports any of it. `tooling/scripts/pack-release.mjs` nonetheless packs every directory
under `packages/`, so an adopter downloads eight tarballs of which several do nothing for
them.

The installation path compounds it. Today an adopter must have access to a private
GitHub Release, download tarballs, run `npm install -D` on them, and only *then* does
`nextgen init` write the `AGENT.md` that tells their coding agent what to do. **The
instructions arrive last.** The requirement inverts this: a developer
should be able to hand their agent — Copilot, Claude, Gemini, Kimi, Qwen, any of them —
a folder path and nothing else, and have the agent read what to do and do it.

A second requirement arrived with it: a place to *see* the result. Judging whether the
router is too dumb or too eager, whether the guided steps read well, whether on-device
voice is usable, and whether the widget's UI is any good, currently means running
`nextgen preview` inside a package. That is a subcommand, not a bench.

## Decision

**The unit of distribution is a directory in this repository, copied by hand or by an
agent. The unit of evaluation is a second directory, which is never exported.**

The top level becomes:

| Directory | What it is | Exported? |
|---|---|---|
| `adapter/` | What the adopter copies. Committed build output. | **Yes — this is the product** |
| `preview/` | The bench: chat UI, role switch, voice, model toggle. | No |
| `packages/` | The source that builds `adapter/`. Six packages. | No |
| `eval/frameworks/` | Fixture applications, one per routing framework, and the harness. | No |
| `eval/field-apps/` etc. | Public applications, ground truth written before the run. | No |

**No application this repository does not own is measured inside it.** Added
2026-09-17, and it follows from the product claim rather than from tidiness: a tool whose
whole assertion is *"it works on a web app it has never seen"* cannot rest its evidence on
one private application, and that application's generated output was its complete screen
inventory annotated by role — the exact artefact
[ADR-014](./ADR-014.md) marks never-serve. The measurement moves to fixture applications in
`eval/frameworks/<app>/`, each with its own `generator.config.json` and golden set, and the
harness takes `--app <name>` so that adding an application is adding a folder.

`adapter/` is self-contained and needs no package manager, no registry and no network:

```
adapter/
  AGENTS.md            the front door — the first thing an agent reads
  scan.mjs             route discovery + registry emit + doctor, one bundled file
  runtime/nextgen.js   the widget, already compiled
  schema.json
```

Three properties make this a decision rather than a repackaging:

1. **`AGENTS.md` is the entry point, not an output.** It ships in the folder, before
   anything has run. Its six `ASK` sections — which the agent must put to the developer
   rather than decide — are kept verbatim from `packages/kit/src/agent-playbook.ts`,
   which was written after a field test where an agent ran the whole install unattended
   and left the developer a bystander in their own project.

2. **`adapter/` is committed build output, and a gate proves it is not stale.** An
   adopter cannot be told to clone and build first; the folder must be copyable as it
   sits. `check-derived-artefacts.mjs` already holds this property for the
   fixture's generated output and is extended to cover `adapter/`. Committed build output
   is only trustworthy while something rebuilds and diffs it: this repo has been bitten
   twice by a staleness step that passed vacuously, which is why the gate is named here
   rather than assumed.

3. **The six demo-only packages and `apps/cli` are deleted from `develop`.** Git history
   keeps them; `git log --all -- packages/core-voice` recovers any of them.

**What is deliberately not lost:** the voice an adopter's users get is
`packages/embed/src/voice.ts` — Web Speech API, `processLocally` enforced, on-device or
not at all. `core-voice` is Whisper and Piper *Windows binaries* for the terminal app.
Deleting it removes nothing from the shipping path, and `preview/` can still judge voice.

## Alternatives considered

**Keep the packages, fix only `pack-release.mjs`.** Cheapest, and it does fix the eight
tarballs. It does not fix the thing actually complained of: the repository still reads as
two products, every gate still runs over 9,700 lines nobody ships, and every future agent
picking this repo up cold still has to work out which half is live.

**Keep npm distribution, move `AGENTS.md` to the front.** Preserves the measured
generator and versioned dependencies. Rejected because the private release remains a
hard prerequisite: the developer cannot try this without being granted access first,
which is precisely the friction being removed.

**Ship instructions only, and let the agent discover routes itself.** The smallest
possible folder, and the most flexible. Rejected because the discovery would stop being
deterministic: `eval/field-apps` found every route in ground truth across six public apps
*because a scanner did it the same way every time*. An agent doing it freehand makes
those numbers unclaimable and makes two installs of the same app differ.

## The reversibility test

**Cheap to reverse.** The deleted packages are one `git revert` away and depend on
nothing that changes here. `adapter/` is generated from `packages/`, so its shape can be
changed by changing a build script. The expensive-to-reverse part is external: once an
adopter has copied `adapter/` into their repository, its layout and `AGENTS.md`'s
contract are what their agent was told to expect. That argues for settling the folder
layout before the first real adopter, not for avoiding the decision.

## Consequences

- `pnpm app` and `pnpm app:offline` disappear with `apps/cli`. `preview/` replaces them
  as the way to see a turn, and shows what an adopter actually gets rather than a
  terminal.
- Rule 1 (`core-*` never imports a domain) loses its subject: there are no domain
  packages left. The boundary it protected — the engine knowing nothing about any
  particular application — is now enforced by the fact that the only application the
  engine ever sees is the adopter's, at run time. `check-import-boundaries.mjs` must be
  repointed or retired; retiring an enforced rule needs its own note in
  `critical-infrastructure.md`.
- **Five gates were repointed rather than retired**, and all five still pass: the
  golden-set scorer, derived artefacts, accessibility, the strict-CSP run and the registry
  validation now read `eval/frameworks/school/generated`. The property each one protects
  was never specific to the private application; only the data was.
- **Measurements made on the private application become unverifiable from a fresh clone.**
  This is the real price of the decision and it is paid deliberately: the measurements happened, and a reader can no longer check them
  here. What generalises was extracted first, into `adapter/FIELD-NOTES.md`.
- `eval/frameworks/school` is a synthetic app that reproduces the hard cases real apps present — one
  screen at two addresses, placeholder titles, a title untranslated in one of two languages
  — so the regressions those caused stay covered without the application that had them.
- `packages/kit` stops being a CLI. `detect`/`build`/`doctor`/`calibrate` are bundled
  into `adapter/scan.mjs`; `preview` moves to `preview/`.

## Compliance

- `node tooling/scripts/check-derived-artefacts.mjs` — `adapter/` matches what
  `packages/` builds. This is the gate that makes the committed folder trustworthy.
- `node tooling/scripts/check-install.mjs` — repurposed: a copy of `adapter/` into a
  scratch directory runs with no `node_modules`, no network, on Node 20.
- `node tooling/scripts/check-csp.mjs` — unchanged; the widget still loads under a strict
  CSP in a real browser.
- The golden-set check in CI — unchanged.
