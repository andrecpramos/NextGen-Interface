# ADR-017 — The script tag escalates to the adopter's own origin, and only when they switch it on

- **Status:** **Accepted — by the owner, in session, 2026-09-18.** Proposed 2026-09-14.
- **Date:** 2026-09-14
- **Amended on acceptance:** point 4 below said *"The visitor is never shown model text
  (Rule 9)."* That is no longer true, and the change is large enough to have its own
  record: [ADR-019](./ADR-019.md). Everything else here is accepted unchanged — the
  same-origin transport, off by default, degradation, and disclosure in *Why?* — and
  ADR-019 depends on all four.
- **Deciders:** the owner chose the options in session on 2026-09-14. The Architect *(an agent)* wrote this record; accepting it is the owner's.
- **Relates to:**
  - [ADR-008](./ADR-008.md): a network call on the core loop needs an ADR, and cloud inference is opt-in, disclosed at use and recorded in the trace;
  - [ADR-013](./ADR-013.md): the product resolves most turns with zero network calls;
  - [ADR-014](./ADR-014.md): one registry per role;
  - PLAN.md §1.4;
  - Rules 8, 9, 15 and 17.

## Context

The script tag (`packages/embed`) runs stages 1 and 2 of the router and nothing else: `create()` passes `useStage3: false`. A turn those stages cannot settle ends in a clarifying question. That was deliberate, because a script tag had no stage-3 transport and a clarifying question is never a wrong answer.

The cost was measured on 2026-09-14, on fut-app's PARENT registry, after the generator was improved to name screens in the application's own words (`eval/fut-app/TITLES.md`):

- **Golden set** (210 turns, calibrated per registry): 15.7% of turns are settled correctly with no model. Top-1 is 11.4%.
- **Twenty questions a guardian would type:** 8 are settled. The other 12 ask the visitor back.

The owner's verdict on the resulting assistant was that it "feels stale". Most of that is the router asking back on turns it could not settle alone.

PLAN.md §1.4 already names the design: *"Stage 3, the model — only for what 1 and 2 could not settle, against an endpoint the adopter configures. Unavailable ⇒ it asks a question, never guesses."* It was never built for the browser. ADR-008 requires an ADR before any network call enters a core-loop path.

**What a stage-3 call carries, today** (`stage3()` in `packages/core-intent/src/stages.ts`):
- the visitor's utterance, fenced as data (Rule 15);
- today's date;
- the current route;
- the registry's one-sentence `domainDescription`;
- up to three candidate capabilities (id, description, parameter types).

The answer is schema-constrained to one of those ids or `out_of_scope`. The model chooses from a list. It never writes text a visitor reads (Rule 9).

**What the egress gate can see.** `check-network-egress.mjs` flags `http(s)://host` literals in runtime code. A relative path is invisible to it. A same-origin transport therefore passes the gate, and the gate cannot tell a same-origin transport from one that is not.

## Decision

We will give the script tag a stage 3 that the adopter switches on, and that talks only to the adopter's own site.

1. **Transport: same origin, no exceptions.** The script tag POSTs the completion request the cascade already builds (`system`, `prompt`, `schema`, optional `model`) as JSON to a path on the page's own origin. The default path is `<bundle base>/stage3`, beside the role's registry files. The transport refuses any address whose origin differs from the page's origin. The adopter's server behind that path decides which model answers and where it runs.
2. **Off by default.** Stage 3 is enabled only when the adopter's build turns it on (`nextgen build`), which records it in the bundle it serves and in `build.json`. No HTML attribute and no visitor setting can turn it on.
3. **Degradation is unchanged.** The transport is an `LlmRuntime` (`packages/core-inference`) and never throws. A timeout, an unreachable path, a non-2xx response or an unparseable body degrades to the clarifying question a visitor gets today.
4. **Every model-decided turn is disclosed.** The turn record keeps `decidedAt: 'llm'`, `modelId` and `latency.stage3`, which already exist in `core-trace`. The assistant's *Why?* disclosure states that a model on the adopter's site chose the answer, from which candidates, and how long it took. The visitor is never shown model text (Rule 9).
5. **Nothing else changes.**
   - The model picks from the role's own shortlist (Rule 17).
   - Stage 2 agreement rules and the fencing of the utterance stay as they are.
   - A stage-3 answer can only navigate or explain, because the script tag has no dispatcher.
   - Thresholds for a bundle with stage 3 on are calibrated with stage 3 on (Rule 14).

## Alternatives considered

**Do nothing: stages 1 and 2 only.** This keeps the strongest property the product has: no visitor's words leave the page, ever. It is also the only option that needs nothing from the adopter's server. It was measured above, and it leaves most natural questions asking back. The better generator and the live-page context are being pursued in parallel and may shrink the gap. They cannot close it for questions that name nothing on the page, such as "how is the team doing in the league". It stays the default: a bundle built without stage 3 behaves exactly as it does today.

**Any HTTPS endpoint the adopter names**, including a hosted model API called straight from the browser. This is simplest for an adopter without a server, and it is how most chat widgets work. The owner rejected it for four reasons:
- The visitor's words would leave the adopter's domain from the visitor's browser, which is a new third party in the adopter's privacy notice.
- A strict `connect-src 'self'` policy, which `check-csp.mjs` tests, would have to be widened.
- A hosted API's key would have to live in the page, where anyone can read it.
- Disclosing "your words went to this company" is a harder sentence to put in *Why?* honestly.

**A model in the browser** (WebGPU or WebAssembly). It needs no server and no network after download. It was rejected on measurements the project already holds:
- A 1B-class model is roughly 800MB against a 30KB script tag.
- gemma3:1b never chose `out_of_scope` across 140 calls (FINDINGS Finding 7), so the refusal path would rest on the weakest model.
- Device capability varies too much to promise a latency.

This remains the right answer if a small model ever routes reliably. The transport interface would not change.

**Ask the visitor before any model call.** This is the strictest option, and it was offered. The owner chose adopter-enabled with disclosure in *Why?* instead, because the extra step lands on every visitor and not on the adopter who made the choice. It can be added later without changing the transport or the wire contract.

**Our own hosted service as the default stage 3.** ADR-008 says `services/api` must never become the default route for stage 3. It would also reintroduce the per-turn cost that ADR-013 exists to avoid.

## Consequences

**Positive**
- Turns stages 1 and 2 cannot settle can be answered, without the visitor's words leaving the adopter's domain from the browser.
- A strict Content-Security-Policy keeps working unchanged (`connect-src 'self'`).
- The adopter chooses the model, where it runs and what is logged.
- A local model on their own server keeps the whole path inside their infrastructure.
- The failure mode is the one that exists today: a clarifying question.

**Negative**
- **The adopters this tag was built for may not be able to use it.** Ladder C3 exists for applications with no build step, and many of those also have no server of their own to proxy a model. For them, stage 3 is unavailable.
- **The visitor's words reach the adopter's server in a new request.** The adopter owns the page already, but this is a new data flow. Logging, retention and the privacy notice are theirs to get right, and this project cannot enforce any of it.
- **It is an unauthenticated POST that spends money or GPU time.** Anyone who can load the page can call it. Rate limiting and authentication belong to the adopter's proxy. A reference proxy that ships without limits would be a trap.
- **A model turn is slower than a stage-2 turn.** Measured on fut-app's golden set on 2026-09-10 (`eval/fut-app/scorecard-ollama-llama3_1_8b.json`):
  - model-decided turns with llama3.1:8b on a local Ollama (187 of them): 415ms p50, 529ms p95;
  - stages 1 and 2 with a neural encoder: 8ms p50;
  - stages 1 and 2 with the shipped hashing encoder: under 1ms.

  An adopter's model behind their own server adds their network and their hardware to that. The latency has to be measured per adopter before stage 3 is enabled, and *Why?* shows it.
- **The utterance reaches a model.** Prompt injection is bounded, not eliminated. The utterance is fenced (Rule 15), and the answer is constrained to three ids the role could already reach. The worst outcome is a wrong but permitted destination, never an action.
- **The egress gate cannot enforce same-origin.** A relative path is invisible to `check-network-egress.mjs`, so the refusal of a cross-origin address rests on a runtime check and its test alone.
- **Two operating points per registry.** A bundle with stage 3 on needs its own calibration, and `nextgen calibrate` has to know which one it is producing.

## Compliance

- **Same origin:** the stage-3 transport's origin check, with a test that a cross-origin, protocol-relative or absolute address is refused and no request is made. *(Written with the implementation. Until then, convention.)*
- **No remote host in runtime code:** the `network-egress` gate, unchanged.
- **Off by default:** a test that a bundle built without the flag never constructs the transport, and `doctor` reports whether stage 3 is on.
- **Disclosure:** assistant tests that a `decidedAt: 'llm'` turn renders the model statement in *Why?*. `check-csp.mjs` is extended to run one stage-3 turn against a local proxy under `connect-src 'self'`.
- **Register:** on acceptance, the Rule 8 rows of `.claude/docs/critical-infrastructure.md` and PLAN.md §2 are updated to name this ADR and the origin check.
