# ADR-022 — The orb is alive from thinking-orbs' engine; the rest is rebuilt in CSS, with no React in the script tag

- **Status:** Accepted — by the owner, in session, 2026-09-22. Proposed 2026-09-20.
- **Date:** 2026-09-20
- **Deciders:** Andre, Architect
- **Relates to:** [ADR-012](./ADR-012.md) — no component framework; [ADR-021](./ADR-021.md) —
  the script tag in `adapter/` is what an adopter receives; [ADR-017](./ADR-017.md) — sizes the
  script tag against a model and calls it "30KB".

## Context

The owner asked for the default look of the widget to be *alive*, and named six packages to get
it: `thinking-orbs`, `border-beam`, `voice-glow`, `liquid-gooey`, `metal-fx` and `img-fx` (all MIT,
one author). The widget is a framework-free script tag with no build step on the adopter's side,
and one gate (`check-csp.mjs`) runs it under `style-src 'self'`, where a `<style>` element is
blocked and renders the screen unstyled.

Checked against the packages as published on 2026-09-20:

| Package | What it is | Needs | Injects a `<style>` element |
|---|---|---|---|
| `thinking-orbs` 0.3.1 | Dotted-sphere loaders, nine states. Exports a **React-free `/engine`**: pure geometry, no DOM | nothing (engine) / React (component) | no |
| `border-beam` 1.3.0 | Travelling glow round an element | React | yes |
| `voice-glow` 0.2.0 | Glow that rises with a voice level | React | yes |
| `liquid-gooey` 0.2.1 | Gooey merging shapes | React, SVG filters | no |
| `metal-fx` 2.0.10 | Liquid-metal ring | React, WebGL2 | yes |
| `img-fx` 0.5.1 | Image-generation shimmer | React, `three`, WebGL | yes |

Four of the six cannot run in the script tag as published: they need a React runtime, and they
inject the one thing the CSP gate exists to catch. The cost of giving them one, bundled with
esbuild on 2026-09-20 against the widget's current **40.0KB gzipped** (1KB = 1000 bytes, `gzip -9`, `adapter/runtime/nextgen.js`):

| Bundled into the script tag | Gzipped |
|---|---|
| React + react-dom/client | **69KB** — nearly twice the whole widget |
| … with `border-beam` | 80KB |
| `img-fx` with `three` and React | 157KB |

`border-beam` does contain a pure `generateBeamCSS()`, but the package does not export it.

## Decision

**We will take the one part of the set that is framework-free, rebuild the visual idea of two
more, and keep React out of the script tag.**

1. **`thinking-orbs/engine` becomes a runtime dependency of `@nextgen/embed`**, bundled by esbuild
   like everything else. `src/mind.ts` draws its dotted sphere inside the orb's liquid body, one
   motion per orb state (idle *breathing*, listening *listening*, thinking *searching*, speaking
   *composing*, error the idle ring), with a half-second crossfade. Only the engine is imported —
   never the React entry.
2. **The `border-beam` and `voice-glow` looks are rebuilt as CSS** (`src/beam.ts`): a travelling
   line while thinking, a level-driven glow while listening or speaking, a slow breath at rest,
   the danger colour on error. It lives in the assistant's adopted stylesheet, so it is
   CSP-safe, and its colours are the orb's accent turned either way round the hue wheel.
3. **`liquid-gooey`, `metal-fx` and `img-fx` are not in the script tag.** Nor are the originals of
   `border-beam` and `voice-glow`. All five are root **devDependencies**, used only by the bench:
   `/alive` (`preview/`) shows the widget's own modules in every state and, beside them, the
   originals running as published, so the owner can judge what an adopter *with* React could add.
   `preview/` is never exported (ADR-018).
4. **The build carries the licence.** `thinking-orbs` is MIT, and its notice must travel with the
   code. `build.mjs` embeds the installed package's own `LICENSE` as a banner and fails the build if
   it is missing or not the MIT text. `legalComments: 'none'` would otherwise have shipped the
   engine with no notice.

## Alternatives considered

**Do nothing.** The orb is a canvas liquid with five states and it works. Rejected because the
owner asked for the opposite, and because the liquid alone does not say *what* the assistant is
doing — listening and thinking differ only in speed.

**Bundle React and all six into the script tag.** The literal reading of the request. Rejected on
the numbers above (+69KB before any effect), on the CSP gate (four packages inject `<style>`;
the gate would have to be loosened or each library patched), and because it contradicts
ADR-012 — the widget was built without a component framework on purpose, and the adopters it
exists for have no build step to absorb one.

**Vendor `border-beam`'s `generateBeamCSS()`** (2,543 lines of generated gradient stacks, plus its
pulse driver) to get the exact original. Rejected for now: it is a large copy of someone else's
generated output to keep in step, and the pieces the composer needs are two thin gradients. The
originals are on `/alive` for comparison, and they are markedly bolder and more colourful than the
rebuild (multi-hue against one accent). If the owner prefers that look, this is the alternative to
revisit.

**A preview-only showcase, with the widget unchanged.** Rejected by the owner: the point is the
default look an adopter gets.

## The reversibility test

**Cheap to reverse.** `mind.ts` is the only importer of the dependency; `createLiquid({ mind:
false })` already draws the liquid alone, and `beam.ts` is one `createBeam` call in `assistant.ts`.
Removing either is a deletion in one package, and no adopter's page or configuration names them.
What becomes expensive after a first adopter ships is not the code but the look they were shown.

## Consequences

- **The script tag grows 32.4KB → 40.0KB gzipped (+7.7KB, +23%).** 5KB of it is the engine, which
  exports all nine motions as one registry although the orb uses four. `packages/embed/README.md`
  said "~30KB"; it now says what is measured.
- **`@nextgen/embed` gains its first third-party runtime dependency**, at `0.x`, from a single
  maintainer. `^0.3.1` admits patch releases only, so a breaking change cannot arrive unasked, but
  a fix we need may not.
- **The rebuilt effects are not the originals.** They are quieter and one-hued. That is a design
  choice as much as a limit, and it is visible side by side on `/alive`.
- **The composer's light is decorative motion on someone else's page.** It is `aria-hidden`, absent
  under forced colours, a still line under `prefers-reduced-motion`, and the state is still written
  in words on the screen. It has not been reviewed with a screen reader or on a real GPU-less
  device; the WebGL demos on `/alive` stalled a software-rendered browser (`img-fx` is
  click-to-run for that reason).
- **Eight development dependencies** (`react`, `react-dom`, `three` and the five packages) now sit
  in the root manifest for a page no adopter sees.

## Compliance

- **Enforced:** `check-csp.mjs` (the widget under a strict policy, no violations); `mind.test.ts`,
  `beam.test.ts` (no `@property`, `url()` or `@import` in the light's stylesheet; every variable it
  reads is one the script sets; a still form for reduced motion); `build.mjs` (fails without the
  notice).
- **By convention only:** that `packages/embed` imports `thinking-orbs/engine` and never its React
  entry, and that the script tag stays near its measured size. No gate fails on either: if
  `mind.ts` imported the React entry the bundle would grow by React's 69KB, and the only sign would
  be the size line `build.mjs` prints. A size ceiling in CI is the obvious gate if a second
  dependency arrives; this belongs in `critical-infrastructure.md`'s gap list.
