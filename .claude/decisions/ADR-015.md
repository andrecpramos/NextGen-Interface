# ADR-015 — Out-of-scope needs a verb signal, not a better boundary

- **Status:** **Accepted** — 2026-09-10, by the owner, in session
- **Date:** 2026-09-10
- **Deciders:** Andre, Architect
- **Supersedes:** —
- **Amends:** [ADR-009](./ADR-009.md) — adds an input to the mechanism; does not change what a
  declared boundary is, who writes it, or that a refusal is authored rather than generated

## Context

[ADR-009](./ADR-009.md) made out-of-scope detection a retrieval problem rather than a
threshold problem: the application declares its limits as capabilities, and stage 2 refuses
when a declared limit out-ranks the best real capability by `boundaryMargin`. It worked, and
it worked *better the worse the model was* — 0% → 40% refusal accuracy on `gemma3:1b`, a
model that never produced a refusal on its own. It is the single most important safety
property in the product, and it is model-free.

**It was measured on a 7-capability registry. On a real one it fails.**
[WP-33](../../eval/fut-app/MEASUREMENT.md) put a generated 145-capability registry for
`fut-app` in front of 34 hand-written out-of-scope requests:

| | 7-capability reference app | 145-capability generated registry |
|---|---|---|
| Out-of-scope detected | 92.3% | **38.2%** |
| Wrongly executed | — | **61.8%** |

```
"paga a minha quota de sócio"                      -> /my/consents
"marca uma consulta no hospital para o meu filho"  -> /my/children/medical
"envia uma mensagem ao treinador…"                 -> /my/agenda
```

**The obvious repair was built and it did nothing.** WP-39 wrote one boundary per section,
carrying that section's own screen titles so a refusal would share the vocabulary of the
requests it must catch. The boundary's score rose materially — for *"marca uma consulta no
hospital para o meu filho"* from 0.594 to **0.690** — and detection moved **zero points**,
because the child-medical page that request must not reach scores **0.761** on the same
words. The code was reverted.

## The finding

**Stage 2 ranks by cosine similarity, and cosine similarity is dominated by topic. What
makes a request out-of-scope here is its verb.**

> *"Show me my son's medical status"* and *"book my son a medical appointment"* are
> near-identical as topics and opposite as requests.

No boundary wording can separate them, because they are about the same thing. ADR-009 gave
the mechanism one input — semantic similarity — and that input does not carry the
distinction it is being asked to make. This is not a tuning failure and not a
boundary-authoring failure. It is a missing signal.

## Decision

**Give stage 2 a second, independent input: whether the utterance asks the assistant to
*perform* an action.** When it does, a declared boundary may win on a lower margin.

```ts
const margin = isActionRequest(utterance)
  ? thresholds.actionBoundaryMargin   // calibrated, and may be <= 0
  : thresholds.boundaryMargin;
if (bestBoundary && boundaryLead >= margin) decision = 'refuse';
```

Three properties make this the right shape:

1. **It is model-free.** A closed list of verbs and a word-boundary match. ADR-009 exists
   because a safety property behind a model call is not a safety property on a small model,
   and putting this one behind a model call would undo its own reason for existing.
2. **It is a signal the model cannot inflate** — the same discipline WP-17 applied when it
   replaced `TAU_ACT_BY_KIND` with stage-2/stage-3 agreement.
3. **It fails in the right direction.** A missed action verb leaves the turn exactly as it
   is today. A false positive is bounded by the calibration constraint below.

### What counts as an action request

**Not imperativeness.** Navigation requests are imperative too — *"abre o calendário"*,
*"mostra-me"*, *"take me to"*. The distinction is *which* verb: verbs the assistant performs
(show, open, go, find) versus verbs it does not (book, pay, send, delete, cancel, change).
This is ADR-009's declared-limits idea moved from nouns to verbs.

**Minus the instructional frame.** *"Como criar uma nova época?"* / *"How do I remove a
task?"* contain an action verb and are **in scope** — a user asking how to do something
themselves is exactly who this product serves, and the right answer is to take them to the
screen where they do it. First person asks for directions; second person asks for service,
so *"podes marcar…"* / *"can you book…"* stays an action request despite being a question.

Measured contribution of that one refinement: in-domain false flags fell from **11.4% to
2.8%** with no loss in out-of-scope coverage.

### The constraint that governs the margin

Unchanged from ADR-009 and `config.ts`: **refusing a real request is the expensive error.**
It tells a user the application cannot do something it can. `actionBoundaryMargin` is
calibrated as the most permissive value that wrongly refuses **nothing**, never hand-set
(Rule 14).

### Required guard: an application that declares the action

`fut-app`'s generated registry is entirely `kind: 'navigate'`, so no capability there
*performs* anything. That is not true in general — `domain-modules` declares `module.delete`,
and *"delete that module"* is an action request the application genuinely serves.

**The gate must not fire when the best-ranked capability is itself `write` or
`destructive`.** An application that declares an action is an application that does it, and
Rule 5's policy table — confirm, and undo for destructive — is what governs it from there.
Without this guard, this ADR would make every reference app refuse its own write path.

## Evidence

Measured by ``experiment-action-verbs.mjs``
against WP-32's golden set on the generated `fut-app` registries, `nomic-embed-text`, split
40/60 by destination so no screen appears on both sides.

**Separation** — the question this whole ADR turns on:

| | Flagged as an action request |
|---|---|
| The 34 hand-written out-of-scope requests | **88.2%** |
| The 176 in-domain questions | **2.8%** |

Compare topic similarity, which separated them not at all.

**Outcome, on the held-out split, at zero false refusals:**

| | Today | With the verb signal |
|---|---|---|
| Out-of-scope refused, **model-free** | 20.0% | **45.0%** |
| In-domain wrongly refused | 0.0% | **0.0%** |

The model-free number beats the **38.2%** that currently requires a model call. The
mechanism gets better *and* cheaper, which is the direction the whole cascade is supposed to
move in.

**It is not a complete fix.** 45% still means most out-of-scope input reaches stage 3, and
the four surviving false positives are genuinely ambiguous (*"I want to delete a task"* is
arguably an action request that the golden set labels in-domain). This ADR moves a number
that had not moved at all; it does not close it.

## Alternatives considered

**(a) Ask stage 3 directly** — one extra field: is this a request to *do* something or to
*see* something? A model is good at exactly this and it costs nothing extra on a turn that
was making the call anyway. **Rejected as the primary mechanism** because it puts the safety
property behind a model call, which is the opposite of ADR-009's reason for existing, and
because 95% of turns already reach stage 3 — it would improve the number without improving
the economics. **Kept as the escalation path**: for what survives the model-free gate, stage
3 can be asked explicitly.

**(b) More or better boundaries** — WP-39, measured, reverted. Zero movement, and ~11 extra
entries per role registry against an open risk that registry growth erodes stage-2 margins.

**(c) Raise `boundaryMargin` globally** — trades in-domain false refusals for out-of-scope
coverage on every turn, including turns with no action verb in them at all. The calibration
curve shows the price: 76.5% detection costs 6.8% of real requests wrongly refused.

## The reversibility test

**Reversible.** One predicate and one threshold in `core-intent/src/stages.ts`. Deleting
`isActionRequest` and the second margin restores today's behaviour exactly; nothing is
persisted, no artefact format changes, and no registry needs regenerating.

The verb lists are the part with ongoing cost: they are per language, and an adopter
shipping a language we have no list for silently gets today's behaviour rather than a wrong
one. That is the right failure, but it is a maintenance surface, and it is the strongest
argument for (a) as a long-run replacement rather than only an escalation.

## Consequences

- **`Thresholds` gains `actionBoundaryMargin`**, calibrated per encoder *and* per registry
  like every other threshold (Rule 14), and `check-thresholds.mjs` must cover it.
- **`core-intent` gains a small language asset.** It is linguistic, not domain knowledge, so
  Rule 1 is untouched — but it is the first natural-language data in a `core-*` package, and
  a future adopter language means adding to it rather than configuring it.
- **Every reference app must be re-measured before this lands**, specifically for the guard
  above: `domain-modules` declares `module.delete`, and a regression there would be this
  ADR refusing an application's own declared capability.
- **The generator should emit boundaries knowing this exists** — the four-entry catalogue is
  sufficient again once the verb signal carries the discrimination, which is why WP-39's
  section boundaries are not being revived.
- **Out-of-scope stays an open risk.** 45% is not 92%, and PLAN.md §9 keeps the row.

## Compliance

- Rule 5 — untouched. The policy table still governs anything that executes, and the guard
  above exists so this ADR cannot pre-empt it.
- Rule 9 — a refusal remains a recorded trace with an authored message, not model narration.
- Rule 13 — the application's limits are still declared in the registry; this adds how the
  engine *reads the request*, not what the application declares.
- Rule 14 — `actionBoundaryMargin` is swept, never hand-set.
