# ADR-013 — The product is a drop-in AI navigation layer for an existing app, not a personal assistant

- **Status:** Accepted — 2026-09-11
- **Date:** 2026-09-09
- **Deciders:** Maintainers
- **Supersedes:** —
- **Amends:** [ADR-005](./ADR-005.md) (scope, not conclusion — see below)

## Context

The engine — a capability registry, a three-stage router, an explainability trace — was
first built inside a single application the project designed end to end. Two product
requirements changed what it is for:

1. **The adopter installs it into their own codebase.** Not a service we run for them, and
   the installer touches nothing of theirs (Rule 16).
2. **It learns their app and becomes an add-on UI layer** covering navigate, read, explain
   **and nothing else** — the "nothing else" enforced by declared boundaries without a
   model call ([ADR-009](./ADR-009.md)), not by a prompt instruction.

An assistant that resolves most turns with no model call can sit in front of every visitor
of every adopter; one that needs a frontier-model call per turn cannot. That argument does
not exist for a single-user app, and it is the reason for this decision.

## Decision

**The product is a build-time generator that reads an existing app's source and roles and
emits a role-scoped capability registry (Rule 17), plus a browser runtime, shipped with the
adopter's build, that resolves most turns with zero network calls.**

The applications the engine was first built inside are not the product. *(They were kept
for a time as reference registries for the generator; [ADR-018](./ADR-018.md) removed them,
and the measurement now runs on fixture applications and public apps whose ground truth is
written before the tool runs.)*

## What this means for ADR-005

[ADR-005](./ADR-005.md) decided: *"the assistant is primary; a complete conventional
navigation structure exists underneath it."* That was written for an app built end to end.

**It does not extend to an installed adopter deployment, and does not need to.** An
adopter's app already has its own routable pages and navigation, and Rule 16 forbids the
installer from touching any of it. Rule 7's guarantee — every screen the assistant can reach
stays reachable without it — is satisfied **by construction**, because the tool is
additive-only: the adopter's own navigation, which covered 100% of their routes before the
assistant existed, keeps doing so after. We do not build a second, parallel navigation
structure for an app that already has one.

## What this means for "nothing on the critical path needs a network"

The rule generalises cleanly and becomes *more* central: stages 1–2 run in the visitor's
browser against the precomputed bundle, with zero network calls. Model escalation is an
endpoint the *adopter* configures and pays for, on their own origin, and no key ever
reaches the browser ([ADR-017](./ADR-017.md), Rule 8). We do not run inference on the
adopter's behalf, and the product holds none of an adopter's user data: the registry and
its index are static artefacts generated at the adopter's build time.

## Alternatives considered

**Keep building an end-to-end assistant for one app, and treat installation into other apps
as a future concern.** Rejected: the cost argument above only exists for the installed
product, and the generator — the hard part — would never be built against an app it did not
design.

**A hosted service the adopter calls.** Rejected by requirement 1: it would put our server
on the adopter's critical path and their visitors' words on our infrastructure.

## Consequences

**Good**

- The engine built before this decision — the cascade, the policy table, `TurnTrace`, the
  registry format — stays valid. Neither ADR-005's conclusion nor the network rule needed
  reversing; each needed a paragraph of rescoping.
- Rule 7 and Rule 16 reinforce each other: additive-only installation is what makes "every
  screen is reachable without the assistant" true by construction.

**Bad, or at least a cost**

- The generator is now the product's quality bottleneck: a registry is only as good as what
  can be read from source an adopter wrote for other purposes. The field notes
  ([FIELD-NOTES.md](../../adapter/FIELD-NOTES.md)) exist because of this.
- A layer that never touches the adopter's code cannot fix anything in it; it can only
  report what it could not read, which is why every skip is reported.

## Compliance

Rule 16 is gated by `check-adapter.mjs`, which fingerprints the application tree before and
after a real run. Rule 7 holds by construction, as above. Rule 8 is gated by
`check-network-egress.mjs`. See
[critical-infrastructure.md](../docs/critical-infrastructure.md).
