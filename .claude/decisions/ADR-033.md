# ADR-033 — The panel names what the app merged in, as options, and lists the app's tours to pick from

- **Status:** Accepted — 2026-09-25, as amended by ADR-035. Proposed 2026-09-24:
  the product owner asked for it ("merge the tutorial and the already existing assistant to its orb options … we
  can select the available tutorials inside the orb's tutorial option")
- **Date:** 2026-09-24
- **Deciders:** Maintainers
- **Relates to:** [ADR-026](./ADR-026.md) — the companion, and "one question, never a menu", which this
  amends for tours only; Rule 7 (every destination is a real link).

## Context

ADR-026 merged an app's own assistant and tour into the orb: `open()` put an unnamed icon in the panel's
header, and `tour(route)` ran on "tutorial". The first adopter has **several** tours per page — a
role tour, a "what's new" tour — and kept its own tour menu (a `?` button with a list) beside the orb,
because `tour(route)` could only start one of them. That is two entry points again. The product owner asked for
the app's assistant and its tours to be options of the orb itself, and for the tours to be picked from a
list inside it.

## Decision

**1. The panel has a row of options, above the composer, for what the app merged in.** Each is an icon
with a visible name — a row of bare icons says nothing to a newcomer. Today there are two: the companion,
by its name (`open()`, moved here from the header), and **Tutorials** (`tours`). The row is absent when
neither is offered.

**2. `companion.tours(route)` lists the app's tours for the page, and `tour(route, id)` starts the one
picked.** Tutorials shows them as a message in the conversation, one button each (at most 12, anything
malformed dropped, a throwing list read as empty — "There is no tutorial for this page."). A pick docks
the panel and starts it, as the `tour` command always did.

**3. "tutorial" lists them when there is more than one**, and starts the only one at once, as before.

**4. This is the one list the assistant shows, and it amends ADR-026 §4 for this case only.** "One question,
never a menu" is about *places*: the visitor asked where to go, and a list of screens hands the question
back. Here the visitor asked for exactly a list — the tours on offer — and nothing is being guessed.
Tours are buttons, not links: they start something rather than going somewhere, so Rule 7 is untouched.

## Consequences

- An adopter with one tour changes nothing; `tours` is optional and `tour(route)` still works alone.
- An adopter with several can delete its own tour menu: the orb carries it.
- The companion's header icon is gone; the same control is in the options row, named.
