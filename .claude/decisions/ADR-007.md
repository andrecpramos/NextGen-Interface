# ADR-007 — Drizzle over SQLite, superseding Drift

- **Status:** Accepted
- **Date:** 2026-08-29
- **Deciders:** Architect, Backend
- **Supersedes:** [ADR-002](./ADR-002.md)

## Context

[ADR-002](./ADR-002.md) chose Drift over SQLite. Its reasoning was about **SQLite versus
document stores**, and that reasoning was correct and still holds:

- The finance domain is relational and analytical
- Category roll-ups need recursive CTEs
- Transfers need real ACID transactions
- Money needs integer storage, never floating point
- Migration tooling must be trustworthy, because financial data loss is unrecoverable

None of that changes. What changes is that Drift is a Dart library and
[ADR-006](./ADR-006.md) moved the stack to TypeScript. This ADR carries ADR-002's
conclusions across, and picks the TypeScript equivalent.

## Decision

**SQLite as the engine. Drizzle as the query layer.**

| Target | Driver |
|---|---|
| Mobile | `op-sqlite` (fast, supports SQLCipher) |
| Desktop | `better-sqlite3` |
| Web | `wa-sqlite` / OPFS, or remote Postgres |
| Remote (optional) | Supabase Postgres — same Drizzle schema ([ADR-008](./ADR-008.md)) |

## Why Drizzle rather than Prisma

- **It is SQL, not an abstraction over SQL.** The Query Engine exposes a fixed set of
  parameterised queries; writing those in something SQL-shaped is a feature. Recursive
  CTEs for the category tree are expressible directly.
- **Type inference from schema at compile time**, which is the property ADR-002 valued
  in Drift's compile-time query verification.
- **No engine binary, no separate query process.** Prisma's architecture is awkward on
  React Native; Drizzle is just TypeScript.
- **One schema definition targets both SQLite and Postgres**, which matters for the
  optional-sync design in ADR-008.

## Constraints this carries forward from ADR-002 — unchanged and binding

1. **The model never emits SQL.** The Query Engine accepts a query id plus typed slots.
   This eliminates the injection class structurally rather than sanitising it.
2. **Money is `integer` minor units plus a currency code.** SQLite has no decimal type,
   and `REAL` for money is a defect that surfaces at reconciliation time.
3. **All timestamps stored UTC**, converted only at the presentation edge.
4. **Migrations tested from every previously released schema**, with a backup taken
   before migrating and restored on failure.

## Encryption

ADR-002 specified SQLCipher. That carries over: `op-sqlite` supports SQLCipher on
mobile, with the key in the platform keystore (Android Keystore / iOS Keychain),
hardware-backed where available.

Desktop encryption via `better-sqlite3` needs a SQLCipher build and is the weaker
link — resolve before any desktop release, not after.

## Consequences

**Positive**

- Same schema language across local SQLite and remote Postgres
- Type inference end-to-end without codegen indirection
- Drizzle Kit generates and checks migrations

**Negative**

- Drizzle is younger than Drift and than Prisma. Its migration tooling is good but
  less battle-tested than Drift's, and this project has a low tolerance for migration
  bugs. Mitigation: the migration test requirement above is not optional.
- Web SQLite (OPFS) is fiddlier than the native drivers.

## Revisit if

Full-text semantic search over memos becomes primary — though SQLite's FTS5 covers
most of that without changing engines.
