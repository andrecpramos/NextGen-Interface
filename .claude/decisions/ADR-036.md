# ADR-036 — Stage 3 asks only for what the turn reads, and asks a reasoning model not to reason

- **Status:** Accepted — 2026-09-25, and made binding as Rule 18. Proposed the
  same day: the product owner asked for it ("improve our product", choosing "Lean stage-3 schema" from the
  findings of the first production integration)
- **Date:** 2026-09-25
- **Deciders:** Maintainers
- **Amends:** [ADR-019](./ADR-019.md) — `prose` is offered only when the visitor asked for an explanation.
- **Relates to:** [ADR-017](./ADR-017.md) (the same-origin stage-3 transport, whose wire body gains `think`);
  output fields compete for a model's attention.

## Context

The first production integration (a 130-screen app, pt-PT, qwen3:14b on a 12 GB GPU) found stage 3 regularly
timing out. Its measurement: with the schema the router sent, the model wrote `capabilityId`, `confidence`
and a `prose` sentence, 59 generated tokens of which prose was 45, in 4.2 s. The same prompt asking only for
`{capabilityId, confidence}` generated 17 tokens in 1.2 s, with the same choice and the same confidence.
Generation, not prompt reading, was the cost. The integration fixed it by rebuilding the schema on its own
server.

Measured again here, 2026-09-25, on this repository's family fixture with qwen3:14b through
`evaluate-golden.mjs --stage3 qwen3:14b --embedder hashing`:

- The schema also offered `reasoning`, which nothing reads (types.ts: "`reasoning` from stage 3 is still
  not carried through"), and `params` on turns whose candidates take none.
- qwen3 reasons before it answers unless told not to. Its reasoning used ~150 of the 200-token budget
  (`num_predict`); a turn that also wrote `prose` was cut off mid-JSON (`done_reason: length`), failed to
  parse, and became a clarifying question.
- **Before:** 8 of the 9 turns that reached stage 3 ended in a clarifying question, each after ~5 s. Top-1
  81.8% (45/55), out-of-scope refused 78.6%.
- **After** (lean schema, `think: false`): all 9 decided, ~0.9 s warm. Top-1 92.7% (51/55), out-of-scope
  refused 85.7%.
- On one turn, asking for prose again made the same choice at 0.7 instead of 0.8 confidence, in ~1.2 s
  instead of ~0.53 s.

## Decision

1. **The stage-3 schema offers only the fields the turn will read.** It always asks for `capabilityId`,
   listed first because some backends generate in property order, and for `confidence`. It asks for `params`
   only when a candidate declares any, and for `prose` only when `isExplanationRequest(utterance)` is true
   ("what is X", "how do I Y"). It never asks for `reasoning`.
2. **The system prompt carries instructions only for the fields offered.** The prose rules and the
   parameter rules are left out when their field is. The knowledge rule "choose the screen where that is
   settled" stays, without "say so in prose".
3. **Every stage-3 request says `think: false`.** `CompletionRequest.think` is new and optional.
   `OllamaLlmRuntime` passes it as Ollama's `think`. The script tag's transport forwards it in the POST body.
   The reference proxy in `adapter/AGENTS.md` passes it on to the model.
4. **Prose a model returns unasked is still validated** (`validateClaims`), not dropped. An adopter's proxy
   may add it, and Rule 4 holds for it either way.

## Why not the alternatives

- **Do nothing.** On a reasoning model under a token budget the answer is cut off and the turn clarifies:
  8 of 9 here. On a non-reasoning model, every turn waits for a sentence nobody reads. Doing nothing pays
  that on every unsettled turn, for every visitor.
- **Raise `num_predict`.** That would make the cut-off rarer, but every turn would still pay for the
  reasoning in time: ~150 tokens at 14–50 tokens/s is 3–10 s. The integration measured that a token budget
  alone fails on a slowed GPU.
- **Leave it to each adopter's proxy to strip fields.** The first adopter did. Every adopter would have to
  rediscover it, and a proxy cannot know which fields the router will read.
- **Offer prose on every turn and tell the model to leave it empty.** The prompt already said so ("Leave
  prose empty when a plain destination is the whole answer"). The model wrote it anyway: 45 of 59 tokens.

## The reversibility test

It can be undone in one file (`stages.ts`), with no migration. A registry is unaffected, and so is the
bundle format. `think` is an optional field that older proxies ignore.

## Consequences

- **A turn that is not an explanation request gets no written answer from stage 3.** Before, the model
  could add a sentence to a plain "take me to X". The destination and the registry's declared `explanation`
  still say what is there. What is lost is the model's own sentence, which the integration found users
  did not miss next to the right screen.
- **The stage-3 prompt changed.** Any committed stage-3 scorecard is owed a re-run. None is committed today:
  the CI gate runs the model-free floor.
- **`think: false` can make a small model worse at an ambiguous choice.** It was not measured on the
  golden set's harder turns with reasoning on and a larger budget. The integration kept reasoning for the
  one call that prepares a change, which stage 3 never does.
- A working model now **executes** "apaga a ficha médica do meu filho" ("delete my child's medical record")
  as navigation to that screen. The golden set expects a refusal. The old prompt makes the same choice once
  the model actually answers (measured: 0.7 confidence with prose, 0.8 without). Before, only the cut-off
  stopped it. The refusal belongs to the declared limits (Rule 13, ADR-009), not to stage 3, and it is
  still owed.

## Compliance

`stages.test.ts` ("stage3 — a lean request") holds the schema's keys and order, `think: false`, and the
prose and params instructions against what is offered. `cascade.test.ts` holds prose to explanation
requests. `stage3.test.ts` in embed holds `think` on the wire. Latency and accuracy are measured, not gated:
`evaluate-golden.mjs --stage3 <model>` (nothing compares top-1 across a prompt change automatically).
