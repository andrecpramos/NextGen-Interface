# ADR-027 — How clever and how bold the assistant is belongs to the adopter: a decide dial, lessons from real use, search, and several roles per user

- **Status:** Accepted — 2026-09-25. Proposed 2026-09-23: the product owner asked for it
  ("leave some of the complexity of the model to the adopter — he might want it smarter, or even dumber")
- **Date:** 2026-09-23
- **Deciders:** Maintainers
- **Relates to:** [ADR-023](./ADR-023.md) — the likely one; [ADR-025](./ADR-025.md) — limits about acting;
  [ADR-026](./ADR-026.md) — the panel and the companion; Rule 14 (thresholds are calibrated, never set);
  Rule 17 (a role's registry is its entitlement); the first integration's field report.

## Context

The product owner is looking for a "minimum acceptable standard" that holds across very different applications,
and found that no single setting is right for all of them: a clinic wants nothing to move without a yes, a
back-office tool wants fewer questions, a content-heavy app is mostly asked about things no screen is. Until
now every lever the adopter had was at build time — `knowledge.json`, calibration, stage 3 — and none was
fed by what visitors actually asked.

The same session asked how the product would fare on an application unlike the first integration — a social network. The
honest answer found concrete gaps, each of which is a general one:

| Gap | Where it showed |
|---|---|
| Questions about content (people, posts, products) match no screen and end in "I did not understand" | any content-heavy app |
| A navigation built from `div`s is invisible to `adopterNav` and `navFrame` | apps built from generic component kits |
| A user with several roles gets one role's screens; merging two roles' shipped indexes on the server is wrong (each is its own vector space: 56 of 56 components differed) | the first integration |
| A phrase two merged roles' screens claim went silently to whichever registered last | the first integration |
| No types for the API an app calls; an integrator read the minified bundle | the first integration |
| Limits declared in English in a Portuguese app; screen descriptions listing UI chrome and empty states; example phrases that only repeat the title; 133 interview questions with no order | the first integration |

## Decision

1. **We will give the adopter a `decide` dial** (`confirm` | `balanced` | `eager`, `data-nextgen-decide`). It
   changes what is done with the router's decision, never the decision (Rule 14 untouched): `confirm` turns a
   decided move into a question ("Shall I open Calendar?"); `balanced` is today's behaviour; `eager` also
   moves when one place is plainly ahead by ADR-023's bar — never on a lone weak match, two equals, a limit,
   or model prose.
2. **We will report what visitors teach it**, and only to the page: a `Lesson` (`question`, `route`, `how`:
   `chose` | `rejected` | `unplaced`, `from`, `offered`) to `onLearn` and as a `nextgen:learn` event, for every
   question the router could not settle and how the visitor settled it. Decisions it made itself, small talk
   and refusals teach nothing.
3. **We will add `scan.mjs teach`**, which turns a log of lessons into `askedAs` phrases in the adopter's
   `knowledge.json`: a dry run with `review/TAUGHT.md` by default, `--write` to apply, `--min` agreeing
   visitors. It holds back a question that may identify someone (an email, a URL, a run of digits) and one
   visitors settled two ways, and lists what no screen answered for the developer to decide.
4. **We will offer the app's own search** (`search: '/search?q={query}'`) first, for a question nothing in
   the app matched. Same-origin paths with `{query}` only. "Nothing matched" means no candidate reaches the
   likely-one floor (0.15, ADR-023's bar — not a new number): in the bench, "fotos de Ana en Oporto" scored
   0.05 on two unrelated screens and was answered "Notificações, or Painel?". The same definition now
   decides what goes to the companion (ADR-026, amended).
5. **The assistant speaks English (the default) and Portuguese, and no other language.** Word packs —
   Spanish, French and German interface files fetched beside the bundle — were built and then withdrawn
   on the product owner's decision, 2026-09-23. A page in any other language gets the English interface; the
   `words` option can still replace any line programmatically.
6. **We will make the shipped index a cache.** `indexFor(registry)` (core-intent) is the function the build
   writes `index.<ROLE>.json` with and the runtime computes one with when none is given; `mergeRegistryFiles`
   unions several roles' registries. `start(base, ['TEACHER','PARENT'])` / `data-nextgen-role="TEACHER PARENT"`
   fetches each role's registry and indexes the union in the browser.
7. **A stage-1 phrase two capabilities claim will name neither** (`buildTriggerIndex`), on the server and in
   the browser alike; stage 2 decides between them.
8. **We will ship `nextgen.d.ts`**, hand-written and held to the real exports by
   `embed/src/declarations.check.ts` — including a check that every declared key exists in the source.
9. **The generator will** declare its catalogue limits in the app's primary language where it has one (pt);
   leave units, controls and empty states out of a derived description; add up to two examples from the
   page's own short labels ("ver elegibilidade"); and order the interview so the ten screens most likely to
   help come first (`screenPriority`).
10. **`doctor` will** say plainly whether a model is used, propose a signed-in landing route for
    `data-nextgen-home` (GUESSED), print the new attributes and the teach loop, and warn when the project's
    `.gitignore` hides `AGENTS.md`.

## Measured

On the reference fixture (`eval/frameworks/school`, 69 golden turns, hashing encoder, no model), regenerated
and recalibrated with items 7 and 9 (the other items change no routing):

| | before | after |
|---|---|---|
| Settled correctly, no model call | 44/69 (63.8%) | **48/69 (69.6%)** |
| Top-1 on the right screen (in scope) | 34/55 (61.8%) | **39/55 (70.9%)** |
| Out-of-scope refused | 10/14 (71.4%) | 9/14 (64.3%) |
| In-scope wrongly refused | 0/55 | 0/55 |
| Out-of-scope wrongly executed | 0/14 | 0/14 |

Isolated: the Portuguese limits alone moved one turn, right ("coach dashboard" → `/dashboard`); the chrome
filter alone moved none (the fixture's pages have none); the page-label examples moved six: four to the
right screen, one explanation to the right screen, one to a **wrong** screen — "onde mudo o meu endereço de
email" now opens `/settings` where `/settings/notifications` was expected — and one out-of-scope request
("order me new boots") is now asked about instead of refused. The number of labels (two) was chosen before
measuring and was not tuned afterwards; tuning it on 69 turns would fit the golden set, not the product.

Bundle: about 58.7 KB gzipped (from 56.5 KB after ADR-026), under the 60 KB test budget.

## Alternatives considered

- **Do nothing.** Every adopter gets the same assistant. The product owner has already found that no single setting
  is acceptable across apps, and the the first integration gaps above stay open.
- **A numeric "confidence" dial** that shifts the thresholds. Rule 14 forbids hand-set thresholds, and a
  number would be meaningless across encoders (Rule 14). The dial acts on presentation instead, over a
  decision that stays calibrated.
- **Learn online, in the browser** — re-rank from clicks at run time. Invisible to the developer, per device,
  and a way for visitors to teach it wrong things that reach everyone. `teach` keeps a person in the loop.
- **Send lessons to a server of ours.** There is none, and there must not be (Rule 8). The page decides.
- **More languages** — built into the script (measured: +4.4 KB gzipped for three, past the budget) or as
  word packs fetched beside it (built, then withdrawn). The product owner keeps the product to English and
  Portuguese.
- **Merge roles on the server** (the first integration's workaround). Depends on minified identifiers, and a concatenated
  index is wrong; merging in the browser with a computed index is exact and needs no server code.
- **Generate the `.d.ts` with a bundler of declarations.** A new dependency for one file; the hand-written
  file with a compile-time check is smaller and cannot silently drift.

## Consequences

- **`eager` sends visitors to wrong screens more often, by design.** The adopter chooses it; `doctor` and
  AGENTS.md say what it trades. `confirm` costs a reply on every move.
- **Lessons are visitors' own words**, handed to the adopter's page. What they keep, and for how long, is
  theirs and their privacy terms'; `teach` holds back obvious identifiers, but a name in plain words ("the
  photos of Ana") passes its check. Every taught phrase is then served to every visitor of that role, as an
  example in their registry.
- **Taught phrases can be wrong.** A visitor who clicked the wrong place teaches it; `--min` and the
  "settled two ways" rule reduce, not remove, that.
- **Page-label examples cost one wrong move and one softer refusal on the reference app** (Measured). They
  are only used when no model and no knowledge wrote the prose, which is exactly the thin case they help.
- **Several roles are indexed in the browser at start-up**: one `embedSync` pass over the union, milliseconds
  for hundreds of screens, and one fewer file to fetch — but the merged index is no longer the measured,
  shipped one; parity rests on `indexFor` being the build's own function (tested byte for byte).
- **A contested stage-1 phrase no longer decides.** A registry that relied on a duplicated trigger now asks
  or ranks instead.
- **English and Portuguese only.** A page in another language gets the English interface, and its visitors'
  "hola" is routed as a question.
- The hand-written `.d.ts` may say less than the source; the check only stops it saying something false.

## Compliance

- **Enforced by tests:** `present.test.ts` (decide; `searchChoice`), `assistant.test.ts` (the dial end to end;
  search; lessons for tap, reply, "neither" and nothing matched, none for decisions, small talk or refusals;
  a throwing `onLearn`; the navigation selector), `script-tag.test.ts` (several roles; English unless the
  page is Portuguese, nothing fetched for it; the new attributes), `registry-browser.test.ts` (`indexFor`
  reproduces every committed index; merge; contested phrases), `teach.test.ts`, `doctor-hints.test.ts`,
  `knowledge.test.ts` (`screenPriority`), `synthesise.test.ts` (chrome filter, label examples),
  `boundaries.test.ts` (language).
- **Enforced by the typecheck:** `declarations.check.ts`.
- **Enforced by gates:** generated-golden and derived-artefacts (the regenerated fixture), adapter-stale
  (the `.d.ts` in `adapter/runtime/`).
- **By convention only:** what an adopter does with lessons, and that `eager` is chosen knowingly.
