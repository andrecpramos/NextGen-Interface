# ADR-039 — Keyboard mashing is recognised from the app's own letter pairs and never reaches a model

- **Status:** Accepted — 2026-09-25 (chosen to build). Proposed the same day,
  drafted from the first production integration's findings at the product owner's request
- **Date:** 2026-09-25
- **Deciders:** Maintainers
- **Relates to:** Rule 1 (the engine knows no application; the test is built from the registry, not
  written into `core-intent`); Rule 8.

## Context

In the first production integration, "asdkj qwpeo zxmn" went matcher → stage 3 (a model call) → companion
(another model call). Each call cost seconds on a local GPU, and the visitor got a clarifying question
about screens the string resembled.

The integration placed a test in front of both models. It is built from letter pairs (bigrams): the 390
pairs that cover 99.7% of the app's own UI text in pt-PT. A message is mashing if it has ≥ 4 letter pairs
and ≥ 50% of them are outside that set, or if every long word is a short repeated unit ("asdasdasd").
Short replies ("ok", "sim", "2") are never judged. English passes on a pt-PT app, because only about a
third of its pairs are rare in Portuguese. Tested on 8 mashing strings and 16 real requests: no errors.
Measured effect: 10–15 ms, no model call, instead of 2 s or more.

## Decision

1. **The common letter pairs are computed in the browser from the registry it already has**, once per
   registry: the smallest set covering 99.7% of pair occurrences in its documents (titles, descriptions,
   examples, knowledge), its translations and its description. *As built, this replaces the draft's "build
   writes them into the bundle": no new file, no bundle format change, and nothing for an adopter to serve.*
   A registry with fewer than 50 pairs judges nothing.
2. **`core-intent` gets `isMashing(utterance, registry)`** (`mashing.ts`), with the thresholds above as
   named constants, run before stage 1. A match ends the turn `clarify` with `trace.mashing` set: no
   candidates, no model call, no companion call, no search offer and no lesson. The widget says "I didn't
   catch that. Tell me where you want to go, or start here:" with places to begin.
3. **Anything under 4 letter pairs is never judged**, and neither is anything containing a digit
   sequence, which may be a code or a number the visitor is reading out.

## Why not the alternatives

- **Do nothing.** Every mashed input costs one or two model calls and gets an answer that pretends it
  understood.
- **A fixed dictionary per language.** It would have to ship in the widget, and it misses the app's own
  vocabulary: names, product words, abbreviations. The registry is already the app's dictionary.
- **Let stage 3 judge.** That is the cost this exists to avoid, and a small model judges it unreliably.

## The reversibility test

It adds a bundle artefact and a turn outcome that adopters' traces will show. It is reversible by removing
both, but it changes the bundle format, so an ADR is owed.

## Consequences

- **A real request in a language the registry does not cover** — a German visitor on a pt-PT and English
  app — may be judged mashing. The fixed reply is harmless, but it is wrong. The threshold should be
  measured on the golden set's other-language entries before it ships.
- **Names and codes**, such as "Kvaratskhelia" or a licence plate, can look rare. The minimum length and
  the digit rule are the guard. It is unmeasured beyond the integration's 16 requests.
- One more file per bundle, a few KB.

## Measured (2026-09-25, as built)

Every committed registry (the reference fixture's three roles, and the router's frozen 7-capability fixture):
**0 false positives** over 198–279 phrasings each (every golden question, every registry title and
example, plus "Kvaratskhelia", German and Spanish sentences, greetings). **10 of 12 mashed strings
caught**. Missed: "qwerty uiop", whose letter pairs are common ones, and "ççççç", which is too short to
judge. No real visitor's input was measured.

## Compliance

`mashing.test.ts` (core-intent): the detector both ways; the cascade ends the turn before stage 1 with no
model call. `present.test.ts` ("keyboard mashing"): the answer offers places and never refuses.
`assistant.ts` `nothingPlaced`: a mashed turn is never searched, handed over or learned — **convention**,
read by the tests of the presenter only.
